# Skywave v1.2.1 — Release Notes

A fix release from the first on-air session (2026-10-12: FLEX-6700 via
AetherSDR, 1 W on 14.085 MHz, received on a nearby Web-888). Real radio
hardware exposed defects that virtual audio cables had hidden. **The wire
format is unchanged (`kWireVersion` and `kProtocolVersion` both 1); v1.2.1
interoperates with v1.2.0, v1.1.0 and v1.0.0.**

## Operator-visible changes

- **TX level is now correct, about 10 dB below what v1.2.0 sent at
  `output_gain_db = 0`.** Re-check drive on first use: raise the rig's
  audio or DAX TX gain, not `output_gain_db`. Positive trims clip.
- **`output_gain_db` is applied once.** v1.2.0 applied it twice, so −5 dB
  gave −10 dB. Halve any existing negative trim.
- **Audio devices can be named:** `input_device = AetherSDR DAX 1`,
  `output_device = AetherSDR TX`. The GUI now saves names.
- **PTT is held until the audio has actually played.** Rigs whose
  interface reports output latency no longer lose the end of a burst.

## What changed, and why

### TX audio clipped on every real interface

Bursts left at about 0.7 RMS with +9 dBFS peaks. Virtual cables pass
float samples above 1.0 untouched, so ST3 never showed it; a DAX device,
a USB codec or a 16-bit WAV clips them. In a clean 16-bit loopback every
M12/M13 frame failed. `kTxTargetRms` (0.22, defined since Phase 1 and
never applied) now sets the level, with peaks around 0.85. Samples are
limited at full scale with a rate-limited `tx: ... clipped` warning, and
`output_gain_db` is applied once (`tx_level_fits_full_scale_and_gain_applies_once`).

### Audio devices selected by index opened the wrong devices

PortAudio indices shift whenever a device appears or disappears: an SDR
client's virtual DAX devices, or a Continuity microphone. A saved index
then opened something else. TX audio could go to the speakers, or the
modem went deaf; it was found as an `st3_killresume` failure.
`input_device`/`output_device` and `--audio-in`/`--audio-out` take a
name, resolved each time the stream opens. A missing named device stops
start-up instead of falling back to a default (`config_audio_device_by_name`).

### PTT released before the audio played

The key dropped when the TX ring drained, while the device still held
10-100+ ms of audio. The worker now holds PTT for the device's reported
output latency + 10 ms (`ptt_release_waits_for_output_latency`).

### Monitor-only stations reported frames ~90 s late

A station that is not listening never runs the engine on a capture, so
the capture climbed the whole retry ladder and the monitor's single look
came at the last rung. Monitor-only, the monitor now takes every rung.
It publishes once the full burst has arrived (the header's airtime arms
burst-end finalization), so lines carry payloads, not header-only
metadata. Live: 4/4 frames with payloads and 3/3 broadcasts reassembled,
~1.3 s after unkey (`test_monitor_worker`).

### NARROW CSS M0/M1 floors corrected to what a frame achieves

The CSS floors were measured on the payload alone (`bertool --css`).
NARROW's payload reaches −19.5/−17.5 dB, but its chirp preamble, sync
and header do not follow it: full frames lost 30% (M0) and 23% (M1)
there. The floors the AMC steers on are now **−16.0/−15.5 dB**, and the
release gate gains a full-frame CSS sweep (`rel_css_frames.csv`).
MID/WIDE/ULTRA M0 already met floor+1 ≤ 10% on full frames. Recovering
NARROW's 3 dB is acquisition work (ROADMAP).

### NARROW M5 designated (CCIR Good) floor −8.5 → −8.0 dB

At 400 trials the old floor+1 point ran 15.2%, passing the 15% fading
gate on slack alone; it runs 12.2% at −7.0 dB. The release sweep's fixed
seed failed that point identically at v1.2.0 and v1.2.1. v1.2.0 archived a
larger re-run instead of correcting the floor.

### Advisor ran every engine tick

It produced ~147 debug lines/s, and its SNR history spanned ~50 ms, so
the AMC trend advice could never form. It now takes one sample per
trusted measurement (`advisor_engine_feed_spans_real_time`).

## On-air tooling (`tools/onair/`, outside the modem)

- **`onair_sounder`** gen/play/score: real PHY frames per mode, keyed
  segments, CW ID at the end; scoring of FER, SNR/EVM, CFO and drift,
  the clock, and TX timing jumps.
- **`flexptt.py`:** PTT bridge for FlexRadio. It keys through the GUI
  client's CAT (`--rigctl`) and has an RF power guard that refuses to
  key above `--max-rfpower` and unkeys if power rises mid-transmission.
- **`kiwirec.py`:** Web-888/KiwiSDR recorder, with live playback into
  an audio device.
- **`jumpfind.py`:** measures TX-chain slips.
- **`station-flex6700.ini`** and **docs/ONAIR_TEST_PLAN.md**.

Found during the session and fixed in AetherSDR, not Skywave: DAX TX
stayed off after a DAX restart; the TX reader cut audio at 32 ms of
backlog and drained too slowly; and DAX packets were sent unpaced.
Sending a ~53 ms cushion ahead into the radio removed the 5.33 ms
silence slips (NARROW robust 2/6 → 6/6).

## Known limitations

See ROADMAP "Open-item review (2026-10-12)" for current measurements.

- **8.8, CSS under LO drift:** MID fails at the 0.1 Hz/s gate (M2/M3),
  and NARROW from 0.05 Hz/s. WIDE is unaffected.
- **AMC on CCIR Good ramps:** 0.80 of the oracle (unchanged).
- **Extreme in-frame drift:** NARROW M4 at 1 Hz/s (25% FER), MID M4 at
  2 Hz/s.
- **Reverse-direction offset after a retune:** harmless inside ±55 Hz.
- **A mid-frame timing slip costs the frame** (optional item: receiver
  re-sync).
- **No LICENSE file** (owner's hold).

Closed since v1.2.0, with measurements in the ROADMAP review: sustained
two-way bulk, churn at Moderate ≤ 16 dB, the ULTRA robust 3 dB deficit,
and the fading tracking floor (WIDE/ULTRA).

Deviations recorded during the gates:

- **The `build-ubsan` tree had UBSan switched off** (`ENABLE_UBSAN=OFF`,
  GUI on). The v1.2.0 "UBSan clean" result most likely ran a normal
  build. Reconfigured per RELEASE.md (`-DENABLE_UBSAN=ON
  -DENABLE_GUI=OFF`, Command Line Tools clang). v1.2.1 is the first
  release whose UBSan leg is known to have run under UBSan.
- **TSan `test_st2` needs about 3700 s on its own**, past the documented
  3600 s budget. Run in parallel with the ASan/UBSan sweeps it timed out
  (with 0 race reports); run alone it passed. RELEASE.md now gives a
  7200 s budget and says to run the TSan leg by itself.
- **The NARROW Good conformance point** (above) failed at 40 trials and
  was corrected, not re-rolled.
