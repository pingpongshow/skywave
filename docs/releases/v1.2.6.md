# Skywave v1.2.6 — Release Notes

A fix release: the full code review's findings, a waveform analysis of
every frame type, and the first test of the VHF-FM profile through an FM
radio and through the whole modem - which found that the VHF profile had
never worked in the real binary. Skywave has never been released, so no
compatibility constraint applies, but **both ends of a link must run
v1.2.6**: START now carries a session id that in-session frames must
match.

## What changed

### VHF-FM

- **The real modem can send and receive VHF.** The worker built its
  48 kHz converters before selecting the band, so a `band = vhf-fm` modem
  kept HF's 1500 Hz centre and +-1.4 kHz receive filter. Its bursts were
  the VHF signal shifted and folded over 0 Hz, and it could not receive a
  correct one. The converters are now rebuilt with the band. Every VHF
  test before this paired engines at baseband, without converters.
- **VHF frames are detected at every sample phase.** The chirp detector's
  4-sample correlation grid was coarser than the VHF chirp's ~1.8-sample
  peak; frames starting between grid points were missed (3-5 of 8 phases,
  every mode). The grid step is now per band: HF 4, VHF 1, at equal cost.
- **VHF bursts stay inside full scale.** VHF's 11 dB PAPR ceiling put up
  to 1 frame in 5 over full scale, where the worker hard-clipped it. Each
  band has its own TX level: HF 0.22 RMS (unchanged), VHF 0.17.
- **FM radio testing.** New FM radio emulator (`sim/fmradio`), `fmsweep`
  (FER vs CNR per mode over ten radio setups), `test_fmradio`, FM link and
  sample-phase cases in `test_vhf`, and a VHF mode for the ST2 world and
  `soak_st2` (`SKW_ST2_BAND=vhf`). Results:
  `docs/conformance/vhf_fm_2026-10-17/`.

### Waveform and timing

- Frame airtime counts the band filter's flush: `computeGeometry` was
  9.8 ms short on every frame, so every timer and capture window derived
  from it ended early.

### Code review fixes

- **Crypto:** retransmissions resend the original ciphertext (no AES-GCM
  nonce reuse); a rejected peer key fails the key exchange; `seal()`
  refuses without a key; key rotation counts frames since the last
  rotation and KEY_UPDATE is echoed before the initiator switches;
  per-stream sequence high-water.
- **Untrusted input:** a non-zero session id is negotiated and
  in-session frames from other ids are dropped; CALL from a third
  station, CALL_ACK, START_ACK, START_NAK and RESUME_ACK are state-gated;
  PHY header fields range-checked (mode 15 hung the receiver); peer
  carrier masks capped and degenerate masks ignored; ARQ and resume
  points, FILE META size, voice frame counts and buffers bounded.
- **Correctness:** TXTEST OFF works; data-port intake budgeted; PTT
  settings apply immediately and failed unkeys are retried; control and
  voice parsers reset per client; voice talkspurt tail flushed and lost
  PTT grant/end recovered; plus the low-severity items in ROADMAP.
- **Config save:** exit saves the live config atomically with mode 0600
  and merges it with the file as it is on disk: runtime changes win,
  edits made to the file while the modem ran and unknown keys survive.

## Measured through the FM radio (25 kHz channel)

| | M4 | M8 | M10 | M13 | M14 |
|---|---|---|---|---|---|
| Floor, dB CNR (FER <= 10%) | 8 | 18 | 22 | 36 | 40 (port flat < 300 Hz only) |

Mobile flutter costs 10-12 dB, a 12.5 kHz channel 2-4 dB; deviation is
the operator's biggest lever (WAVEFORM.md "operator level").

## Known limitations

- **M14 needs a data port flat below 300 Hz.** The VHF plan's lowest
  carrier is at 300 Hz; a port that rolls off there caps the received SNR
  at ~32 dB and the AMC tops out at M13. Moving the first carrier up
  would fix it at the cost of a waveform change and a floor
  re-measurement (owner's decision, open).
- VHF false detections on noise rose to 13 per 30 min (HF 7, VHF before
  2); each costs one failed decode attempt.
- NARROW on the Moderate floor at 6 dB passes 4/6 seeds (as v1.2.5).
- Simulation results; on-air confirmation (HF and FM) is pending.
- No LICENSE file (owner's hold).
