# Skywave v1.1.0 — Release Notes

A correctness and link-adaptation release. v1.0.0 shipped a latent
decode bug that killed sessions on any fading channel deep enough to
force a demotion, and a MAC that had never been measured under
two-station half-duplex traffic. Both are fixed. No wire-breaking
changes: `kWireVersion` / `kProtocolVersion` are unchanged, so v1.1.0
interoperates with v1.0.0.

## The bug that mattered

**The receiver applied the session carrier mask at every mode; the
transmitter applied it only at M8 and above.** After a mask update
followed by a demotion below M8, every DATA frame failed to decode —
the two ends were reading different subcarrier sets. This is the root
cause of the fading stalls that had been chased through several
sessions under other hypotheses. Fixed with a single shared predicate,
`modeUsesCarrierMask()`, used by both paths, plus a regression test
that was verified to fail against the old receiver.

## Link adaptation, now measured rather than assumed

- **Reported SNR is calibrated.** The OFDM estimator was optimistic by
  4–11 dB depending on family (`kOfdmSnrCalDb`), so the AMC was
  comparing an inflated estimate against honest floor tables and
  promoting into modes that could not hold. Data-aided EVM SNR and a
  convergence gate back it up.
- **Promote/demote margins are explicit and negative on purpose**
  (−1.5 / −3.5 dB): a rung is worth roughly 1.5× the one below, so the
  throughput optimum sits below the one-shot floor.
- **A penalty box** remembers rungs that just failed, so the AMC stops
  re-trying a mode that a channel has already refused.
- **A channel classifier** (Static / Fading / Moderate / Severe) picks
  the floor table, on a median-of-9 pilot window rather than an EMA.
- Measured and **rejected** on evidence, with the numbers recorded in
  ROADMAP.md: multi-rung promotion, promote-at-announce, a
  mode-following delivery bound, a mid-tier window of 8, robust-tier
  frames-per-burst of 2.

## MAC: scheduled turn-taking

A PACTOR/VARA-style ISS/IRS turn scheduler (`CAP_TURN_SCHED`), with
handover at a window boundary, a break-request bit, drain-before-grant,
and grant reclaim after three unanswered grants. CCA/LBT remains where
it is actually correct — control, ACK, handshake and voice bypass the
gate. Overhead work since: minimum hold raised from 2 to 4 round trips
with a 6 s floor, an ISS busy-hold that stopped the granter keying over
its own grant burst tail, a drain fast-retransmit that replaced a
two-ARQ-timeout wedge, and the HF fast-tier ARQ window raised from 8 to
16 at M10+.

## Conformance floors corrected

Two published floors were optimistic and had been failing their own
conformance sweep since the entries were set — the archived v1.0.0
sweep shows both misses, so this is a long-standing error, not a
regression.

| Entry | Was | Now |
|---|---:|---:|
| NARROW M9, AWGN | −0.5 dB | +0.5 dB |
| WIDE M11, fading | 16.0 dB | 17.0 dB |

A `docs_floors` ctest now asserts that every OFDM floor published in
WAVEFORM.md equals `kFloors`, because three NARROW rows had drifted
from the code unnoticed.

## Release engineering fixes

- **The ST3 hardware gate could never run, and could appear to pass.**
  It was disabled through a generator expression over an environment
  variable, which evaluates at configure time, so the documented
  `SKW_HARDWARE_TESTS=1 ctest -L hardware` executed nothing and still
  exited 0. It is now a CMake cache option.
- THIRD_PARTY.md now carries tested versions, the LGPL-2.1 caveat on
  Codec2, and the fact that KissFFT and GoogleTest were never vendored
  despite the planning docs.
- CONFIGURATION.md documents about 40 environment knobs; it had listed
  three. The diagnostic A/B levers are marked as such, with defaults.

## Known open

- **No LICENSE file.** Skywave's own terms are undefined, which blocks
  any public distribution. Owner decision; see RELEASE.md gate 7.
- Goodput falls under a deep offered queue; the soak harness's own feed
  window was found to be the confound in earlier measurements and the
  underlying effect has not been separated out.
- Mid-tier (M7–M9) container starvation is measured but unfixed; the
  window is left at 4 because 8 regressed a seed that had been passing.
