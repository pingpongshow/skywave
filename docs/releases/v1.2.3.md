# Skywave v1.2.3 — Release Notes

Receiver, acquisition and link work measured after v1.2.2. The CSS
preamble on NARROW and MID and the robust-tier cell layout at M5–M7
change on the air; Skywave has never been released, so no compatibility
constraint applies, but **both ends of a link must run v1.2.3**.

## What changed

### CSS deep tier: acquisition and drift

- **12-rep CSS preamble on NARROW and MID** (1.92 s; balanced, chosen by
  exhaustive search). The detector compares patterns of different
  lengths on a length-normalized score and judges every start against
  the noise floor of its 4-rep decision point, so every other signature
  and family detects exactly as before.
- **Runner-up preamble signatures**, a **soft and combined CSS header**
  (ML Hamming per copy, then the two copies' summed LLRs), and a 3.0
  sync bar.
- **CFO branch handling:** the sync window spans ±1 branch on NARROW and
  re-syncs; a CSS frame whose payload failed is re-received at ±1 and
  ±2 branches (6.25/12.5 Hz) with the sync check off, and the CRC
  decides. NARROW M1's "payload limit" was really branch errors.
- **Drift:** the payload search estimates the drift rate from pass 1's
  own pilot offsets (6–7 passes instead of 23, ~2.3× less CPU), failed
  headers are re-walked at the estimated rate, and search passes start
  from the sync tap profile. Every family holds 0% at ±0.3 Hz/s.
- **RAKE taps reach 3 ms:** WIDE/ULTRA CSS on CCIR Poor failed 91–100%
  at any SNR (CCIR Poor's 2 ms path was outside the ±3-chip span).

### OFDM

- **Drift retry pre-derotates the rate** fitted to the first walk's FLL
  trace: NARROW M4/M5 at 2 Hz/s 17.5/10% → 2.5/0%.
- **Leftover spread cells at M5–M7 carry extra copies** of their sources
  (rate unchanged; energy moves into the payload where it is the limit).
  NARROW M5 at its floor 73 → 13%; M5/M6 floors 0.5–1.5 dB lower.

### Link

- M7–M9 burst containers gather every due retransmission and top up with
  new segments.
- A one-way data sender sends a standalone ACK when the peer's signal
  arrives ≥ 2 Hz off, so a retune re-aligns both directions.
- The TCP server accepts an immediate reconnect over a client that just
  closed (the companion app's Connect after its auto-connect failed).

### Floors

All CSS M0–M3 floors are now full-frame floors (AWGN and the three
fading tables), 1.5–3 dB lower than the payload-layer values they
replace, and OFDM M5/M6 floors moved with the leftover copies.
Details and curves: ROADMAP and `docs/conformance/`.

### Test infrastructure

- The ST2 two-modem world is deterministic: same seed, byte-identical
  output under any load. `SKW_ST2_FAMILY` selects the family.
- The payload-only `bertool --css` sweep and its legacy modem-layer API
  are removed; `--css-frames` is the CSS gate.

## Known limitations

- **NARROW link in the ST2 world fails** (pre-existing; found while
  soaking other families; PHY sweeps healthy) - under investigation.
- The AMC, drift, acquisition and floor changes are simulation results;
  on-air confirmation is pending.
- No LICENSE file (owner's hold).

After the gates, two fixes went in without re-running the long gates
(owner's instruction); the full default suite (44/44) and the CSS
full-frame gate passed on the final code:

- **TCP reconnect** (found by the companion app's end-to-end test): the
  server refused a client reconnecting the instant it closed.
- **No retries on truncated captures:** the soak ran 1911 cycles (v1.2.2:
  2175), which first looked like the v1.2.2 drift-retry problem. The
  runner-up and CSS branch retries were running on captures still being
  received; both now skip them. 15-minute real-device soaks then varied
  226-311 cycles across configurations with no consistent ordering, so
  the 2 h figure is within this soak's run-to-run spread (v1.2.2's two
  candidates: 1919 and 2175) rather than a measured regression.
